# 设计：功能切换级联菜单 ＋ 逐帧截图

日期：2026-10-11
状态：已获用户批准（2026-10-11，经逐项 grilling 确认）

## 需求

1. 裁剪按钮右侧加入级联菜单（▾），用户可点击切换主按钮的功能。
2. 新增「逐帧截图」功能：点击后按标记范围将范围内每一帧提取为图片。

## 已确认的关键决策（grilling 结论）

| 决策点 | 结论 |
| --- | --- |
| 菜单与按钮结构 | 分体按钮：主按钮执行当前功能，▾ 弹菜单切模式 |
| 标记行为 | **全局维持现状**（吸附关键帧＋跳转），截图也用吸附后标记范围，不引入原始帧概念 |
| 截图端点语义 | 双端包含 `[起点帧, 终点帧]`，与进度条高亮区域一致 |
| 大范围确认 | **不要**任何确认弹窗，点击立即开跑 |
| 输出格式 | PNG / JPG（质量 95，ffmpeg `-q:v 2`）二选一 |
| 格式选择位置 | 主按钮下方 radio 行，**仅截图模式显示** |
| 输出目录 | 视频同目录，不弹目录选择 |
| 文件命名 | 帧号命名，位宽＝视频总帧数的位数（全序列等长）；同范围重跑覆盖旧图（`-y`） |
| 进度窗 | 简化款：进度条＋百分比＋已输出张数＋中止；出错才弹详情 |
| 其他默认 | 截图时先暂停播放；模式与格式仅会话内记忆；中止保留已生成图片；未标记端默认整片 |

## UI：分体按钮＋模式切换

`cut_row`（video_cutter.py:226）内改为居中的复合 frame：

- 主按钮 `tk.Button`（宽 20，样式不变）：裁剪模式文字 `✂ 裁剪` / command `cut_video`；截图模式文字 `📷 逐帧截图` / command `extract_frames`。
- 右侧紧贴 `▾` 小箭头按钮（宽 2，relief/bd 与主按钮一致），点击在按钮下方弹出 `tk.Menu(tearoff=0)`。
- 菜单为 radiobutton 项：`✂ 裁剪`、`📷 逐帧截图`，当前模式打勾（`tk.StringVar` 绑定）。
- 模式存 `self.action_mode`（`'cut'` | `'frames'`），仅会话内记忆，不持久化。
- 截图模式下主按钮下方出现一行 `ttk.Radiobutton`：`(●) PNG  ( ) JPG（质量 95）`，变量 `self.fmt_var`（`'png'`/`'jpg'`，默认 png）；切回裁剪模式 `pack_forget()` 隐藏。
- 主按钮不做 disabled 预设，点击时校验（与现状一致）；未打开视频时弹「请先打开一个视频文件」。

## 标记与范围（无任何标记逻辑改动）

标记、吸附、高亮、状态栏全部维持现状。截图范围直接取 `mark_in_frame` / `mark_out_frame`：

- 未标记的端：起点取第 0 帧，终点取 `total_frames - 1`（整片）。
- 双端包含：张数 = `终点帧 − 起点帧 + 1`（两端标记吸附到同一关键帧时即 1 张，合法）。
- 仅当 `终点帧 < 起点帧` 报错「起点必须在终点之前」。

## 截图流程

`extract_frames()`：校验视频 → 解析范围 → 播放中先暂停（与裁剪一致）→ 弹简化进度窗（`grab_set` 模态）→ 后台线程执行 ffmpeg：

```
ffmpeg -y -ss {起点秒} -i {视频} -frames:v {张数} -start_number {起点帧} [-q:v 2] {basename}_%0{W}d.{png|jpg}
```

- `-ss` 放 `-i` 前：快速定位到关键帧后逐帧解码丢弃，精确到起点帧；用 `-frames:v` 精确控制张数（不用 `-t`，避免时长取整差帧）。
- 起点秒 = 起点帧 / fps（fps 已有 <1 兜底 30）。
- 位宽 W = `len(str(total_frames - 1))`；OpenCV 读不到总帧数（<2）时按时长×fps 估算，仍不可得兜底 6 位。
- `-y`：同范围重跑覆盖旧图；不同范围因帧号命名互不覆盖。
- RM/RMVB 直接由 ffmpeg 解码截图（无需 mkvmerge，仅无损切割受 Real 封装限制）。

## 进度窗（简化款）

- 头部：`{起点时间} → {终点时间} · N 张`。
- 进度条＋百分比；实时行「已输出 M 张（文件名）」，文件名由 pattern % (起点帧 + M − 1) 得出；进度 = 已输出/总数，解析 stderr `frame=` 行驱动。
- 「中止」按钮：kill 进程（登记 `_running_procs` 保证退出清理；复用 `_cancel_requested`，与裁剪同款模态互斥），**保留已生成图片**，提示已输出张数。
- 成功：窗口显示张数与输出目录，状态栏同步；点「关闭」时**调用 `_close_video()` 关闭文件并复位主界面**（与裁剪完成流程一致，2026-10-11 追加），状态栏保留完成信息；失败：窗口标红并在 `messagebox` 显示 stderr 尾部（约 400 字符），窗口保持打开可关闭。中止/失败路径的「关闭」仅销毁窗口，不关闭文件（同裁剪）。

## 已知边界

- RMVB 为可变帧率，OpenCV/ffmpeg 的 fps 均为均值，起点可能偏差 ±1 帧；截图工具精度下可接受，与裁剪同源不单独处理。
- 位宽按估算值落盘后若实际帧号超出估算位数，ffmpeg 自动加宽该文件名（仅发生在元数据异常的文件，可接受）。
